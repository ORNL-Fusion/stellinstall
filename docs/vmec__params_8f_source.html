42 ! VERSION INFORMATION HISTORY
43 !
44 ! 8.00
45 ! a) added lforbal logical to fbal module to control whether to compute the flux-averaged
46 ! force balance equation printed in the threed1 file. This requires a modification of
47 ! the m=1,n=0 forces for R,Z in tomnsps subroutine. This works well, generally, and
48 ! yields an improved <EQUIF> in threed1 file. However, there have been some cases where
49 ! this non-variational departure fails to converge.
50 ! b) added "bias" to iotas in bcovar when determining preconditioner for very small iota
51 ! values. Seems to need this for improving convergence of preconditioned current-hole cases.
52 ! Eliminated in v8.20.
53 ! c) added "totzsps,a_hess" to recompute r,z,l rapidly for only those modes that are jogged during
54 ! Hessian calculation. NOTE: need to do this for lasym=true case, as well, eventually
55 ! 8.20 (August, 2004)
56 ! a) removed 2-pt tie at origin for m=1 modes, to preserve tri-diagonal structure of Hessian.
57 ! This is needed for preconditioning, which assumes block-tridi structure of equations
58 ! b) fixed problem with free-boundary preconditioner, namely, ctor can not be extrapolated
59 ! at edge when computing preconditioner, because this breaks tri-diagonal structure
60 ! c) added new variables to input file to control preconditioning:
61 ! 1) PRECON_TYPE: = 'default', default tri-di (block size = 1)
62 ! = 'cg', block tri-di, conjugate-gradient time-stepper
63 ! = 'gmres', " ", gmres time-stepper
64 ! = 'tfqmr', " ", transpose free qmr
65 ! 2) PREC2D_THRESHOLD: value of (unpreconditioned) forces at which block (2D) preconditioner
66 ! is turned on (=0 block preconditioner never turned on); recommended
67 ! (default) value ~ 1.E-10, or smaller, if convergence is poor
68 ! 3) LFORBAL: logical variable (default = .true.); when true, the force balance
69 ! used in the threed1 file is used to evolve the m=1 R,Z components. This
70 ! is a non-variational departure from the force equations for these modes,
71 ! but generally does not have an unfavorable impact on convergence.
72 ! d) added new internal variable, ICTRL_PREC2D, to precon2d module. Replaces previous lprec2d
73 ! and iequi>1 variables.
74 ! e) removed lsweep_fast option from module precon2d. This slows the computation of the Hessian
75 ! by about 2/3, but is more accurate (includes pdamp, liota, lforbal correctly)
76 ! f) removed lflam logicals from bcovar and tomnsps, since now we must compute dFlam/dR,Z by
77 ! jogging
78 ! g) removed Compute_Hess_Flam_RZ from lamblks; this is now computed via jogging
79 ! (also removed Get_dFlam_dRZ, FFT2Hessian, Forbal_avg, GetGsqrtVar supporting routines)
80 ! h) removed internal liota logic, used to push iota profile rather than solving for it. Had
81 ! needed this for symmetric Hessian (lsweep_fast=true option), but no longer required. Also,
82 ! it was not implemented entirely correctly for lforbal=true case
83 ! i) for lasym m=1 constraint rsc = zcc, changed xc array so that R+ = .5*(rsc + zcc) is stored at
84 ! xc(rsc,m=1) and R- = .5*(rsc - zcc) is stored at xc(zcc,m=1). In residue, gcz(R-) == gcz(zcc)
85 ! is zeroed by "evolving" gcr(zcc) = azd*[xc(zcc)-xcint], and gcr(rsc) => .5*[gcr(rsc) + gcz(zcc)]
86 ! is evolved. In totzspa, the real rsc and zcc are computed from the internal representations
87 ! (check convert call, too) by calling a new routine convert_asym (also called from wrout before
88 ! writing out xc info). In readin, the original R+,R- are stored, so that for external "jogs",
89 ! there will be no change in forces. All these changes are needed to obtain an invertible Hessian.
90 ! j) added m=1 constraint for 3D case (similar to (i)), rss(n) = zcs(n), for n != 0. Imposed this
91 ! on forces by adding routine constrain_m1 in residue. Added convert_sym routine to totzsp to convert
92 ! from internal xc representation TO internal one.
93 ! k) Decreased exponent on pdamp factor r2 (in bcovar) from 2 to 1, to give better conditioning
94 ! especially for current hole cases
95 ! l) Eliminated iotas bias for determining preconditioner, previously added in v8.00 for stabilizing
96 ! current hole cases (not needed with corrected preconditioner)
